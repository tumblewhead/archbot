## 2. Mathematical trace and actual observations

Let a finite trace `tau` be a word over these observable boundary events. Their position `i` defines order only, not elapsed time. `e` and `n` below are specification labels unless an interface explicitly carries or reconstructs them.

| Event | Meaning and required precedence |
| --- | --- |
| `attempt(t,x)` | Publisher presents a value on transaction `t`; attempt count is not accepted rank. `t` names a transport invocation, not inherently an ordinal. |
| `reject(t)` | Explicit invalid-value rejection/precondition indication. No accepted history, association state or debt change. |
| `accept(t)` | Prospective valid-input acceptance point; binds current logical sequence, value and a result obligation. Chosen before execution and never retrospectively undone. |
| `commit(t)` | Numeric computation/state transition is committed and an exact result is staged. Follows acceptance; is distinct from delivering it. |
| `publish(t)` | Staged frame becomes available to the output channel. Follows commit. Publication alone does not prove consumer receipt. |
| `receive(t)` | Actual consumer obtains the frame and decodes its association. Follows publication. The `t` in the trace is observer instrumentation; S's decoder never receives it. |
| `reset_start`, `reset_complete` | Start a reset interval; completion establishes fresh zero history/rank. Acceptance is excluded during this interval by both proposed contracts. Old debt remains. This exclusion/coordination is a proposed condition, not granted publisher suspension. |
| `restart` | Consumer runtime restarts at a modeled event boundary. Detector history/rank does not reset. Retained consumer state depends on an explicitly named assumption. |
| `retry(t)` | Reference to an existing acceptance; does not append history. A new attempt followed by a new acceptance is a different event even if its value is equal. |

For sequence `e`, let `A_e(tau)` be the list of values with preceding valid `accept` events since reset completion. On the nth such event define

`gamma=(e,n)`, `E_gamma=sum(A_e[max(0,n-32):n][j]^2 over that slice)`.

Conceptual zeros occur only before sequence initialization. Define `D(tau)` as accepted event identities without a correctly decoded logical receipt. For this study the conservative end-to-end discharge point is receipt: acceptance adds one element, legitimate receipt removes it once; commit/publication/rejection/fault/reset/restart do not remove it. Transport may deliver multiple copies only if a specified deduplicator preserves one logical result and still binds them to `gamma`. For every completed study trace, the oracle checks each requested receipt against the exact required triple. Invalid/absent receipt remains unpaid even if a script requests it.

The added `e` disambiguates sequences; it is not an extra numeric-AS output requirement. The accepted observable within one sequence remains `(n,E_n)`.

## 3. Alternative physical refinement contracts

### S: synchronous ordered response with consumer-held accepted context

S1: Identify K-S as the serial caller that receives **every accepted success** in order. At most one acceptance is outstanding. Invalid attempts produce a distinct rejection and no success. Missing success, duplicate success or another consumer accepting unseen events violates S1.

S2: Before acceptance, an input slot, complete numeric transition context and one result slot are reserved. On acceptance debt exists even if subsequent work stalls. Publisher and caller coordinate so the next valid sample is neither lost nor accepted without capacity. This is an unsupplied lossless flow contract. A block-on-full API alone does not establish that an independently acquiring publisher loses nothing.

S3: `commit -> publish -> receive` is an ordered reliable rendezvous, conditional on the peers progressing. Result staging lives through the rendezvous. No universal fault recovery is inferred. A reset starts/completes only after prior accepted results are received; the same ordered interface then supplies a reset-completion marker before new success. A separate ACK is unnecessary. A stalled old result can prevent reset completion; no deadline or permission to drop it follows.

S4: K-S initializes `(s,r)=(0,0)`, increments `r` only on success, and changes `(s,r)` to `(s+1,0)` only on that marker. It retains this exact context across the modeled restarts. This witness assumes action-boundary restart with retained context, not a crash halfway through receipt/state update. A real design must specify atomicity/recovery or the supported failure boundary.

S5: No bound on accepted rank is introduced. The decoder is `decode_S(success(E),s,r)=(s,r+1,E)` followed by `r:=r+1`. Induction: after k successful accepted events since the marker, `r=k`; invalid rejections leave it unchanged; S1 supplies exactly the next event; S3 orders resets. This proves the refinement **conditionally** for every finite k if S1–S4 and exact unbounded arithmetic/storage hold. It does not make the exact context a finite physical object.

`OrderedConsumer` is an executable instance of that decoder. Detector-side S has no ordinal counter. Its one-live-result coordination can be bounded under S1–S3, but K-S's ordinary binary count requires `L(n)=floor(log2(n))+1` value bits for n>=1; reset context also grows in this implementation. Retaining the complete input/result transcript instead only moves the growth. If K-S has strictly finite closed information and receives only energy/reset markers, S cannot support unrestricted exact rank (BC2 below). It needs a reviewed growing external context, another concrete representation with a proved information source, or a separately authorized behavior amendment. No such source is hidden in the induction.

Applying S to C additionally requires H-C. S supplies no history service. Applying it to A/B still needs consumer identity/persistence and publisher coordination; local numeric tails do not supply them.

### X: explicit sequence/ordinal frames with retained transport obligations

X1: H-X maintains exact `(s,n)`, increments n on valid acceptance only, increments s and resets n at explicit reset completion, and binds that identity to the accepted input and numeric result. This requires a provider/authority contract. Acquisition ordinals are insufficient when invalid attempts exist.

X2: A result is the atomic framed object `F=(bin(s),bin(n),E)`, canonical unsigned binary strings without leading zeros; n>=1. Tuple boundaries in the model stand for an assumed transport framing capability, not an implemented byte protocol. Ordered `RESET(bin(s))` completion frames precede new-sequence results at the consumer. Old results may arrive after the marker, in either order relative to new results. Consumer K-X decodes the actual fields, so it need not infer rank from arrival order. It retains last reset sequence to check marker order and rejects future-sequence results before their marker.

X3: Existing accepted numeric commitments are fenced before reset in this modeled contract. The new numeric state can then reset while immutable old result frames and debt survive. `G03` tests the explicit stronger order `old commit < reset_start`; it does not test an old numeric write racing a new sequence. H-X must preserve old frame identity until all buffers, retries and consumer references that could alias it are retired.

X4: A lossless response store/transport preserves every accepted result until receipt or a proved handoff to another responsible store. Retrying an existing identity returns that same result and does not reaccept the input. K-X's retained `seen={(s,n)}` set provides the model's logical deduplication; transport copies are not new logical results. An implementation must establish safe deletion or bound/charge this growing set. Restart preserves `seen` and reset context in this witness. No at-most-once/exactly-once physical transport or general crash durability is proved.

X5: Decoder `decode_X(F)=(parse(bin(s)),parse(bin(n)),E)` is explicit. With X1/X2, each fresh accepted identity has exactly one required logical frame, and X4 preserves its association through stall/reset/retry. Injectivity of canonical binary gives exact n at every finite rank, independently of arrival order. This conditional argument is independent of Python's finite test coverage. The witness parser materializes the strings/integers; it is not a constant-memory streaming parser proof.

X6: H-X must supply potentially growing numeral/reset storage and transport and arbitrary outstanding debt unless another proved operating envelope bounds it. Numeral payload length is L(n); sequence payload is L(s) for s>0. Lossless streaming may bound detector staging, but still needs a real serializer/parser, source state, per-event bit work and retention/availability proof. Finite tags alone are not X. With no authorized provider, X remains an open supplier contract, not a feasible physical service discovered by this study.

X can accompany A or B as an additional index/transport dependency; it does not reduce their numeric state. C needs both X/H-X and H-C in this variant. H-C must bind an immutable **pre-event** tail, current sample, identity and reset to one acceptance; remain available through reduction or an equivalent retained result; and report errors without padding, erasing acceptance or treating an error as E.

### What can be bounded, and what remains unresolved

Both contracts offer concrete finite **local coordination** mechanisms under their proposed assumptions: S can have one input/result staging slot and drain before marker; X can use bounded live slots only with a justified occupancy envelope/flow contract and safe identity retirement. Neither grants that envelope under the existing publisher authority. Neither provides a finite closed unrestricted-rank consumer. The AS bounds detector RAM, not every conceivable external consumer/store; therefore the missing external contracts are not a universal full-AS impossibility proof. Whether the intended actual environment can support either contract without a material behavior change is still UNKNOWN.

## 6. Resources, lifetimes and F

Let bytes be representation-dependent: `b_x` raw sample (12 value bits), `b_q` square (24), `b_E,b_S` totals (29), `O_c` order/control. Define `I_D(t),I_K(t),I_U(t)` exact-rank/reset representation bytes by owner; `d(t)` accepted unpaid count; `z(t)` live reset contexts; `r(t)` retained retry identities; `p(t)` pinned snapshot versions. `L(n)=floor(log2 n)+1` bits for ordinary positive binary n. Bytes for that payload alone are `ceil(L(n)/8)`; framing, alignment, objects and state add costs. No term is assumed constant if its lifetime/rank can grow.

`RAM_D,c = max_t [N_c(t)+O_c(t)+I_D(t)+Debt_D(t)+Reset_D(t)+Retry_D(t)+Stage_D(t)+Scratch_D(t)+Stack_D(t)+SharedAttr_D(t)]`.

Each live allocation is counted once. If an accumulator/result resides on the counted stack, do not add it again as scratch/staging. Use a simultaneous maximum, not an asserted saving from unrelated per-term peaks.
