# CLN-001 IF11 engineering briefing

Two concrete candidate consumer refinements now have executable decoders and conditional supporting arguments. They make different information and lifetime demands. **No authorized provider or complete physical implementation was established, and A/B/C remain unselected.**

The [feasibility dossier](IF11_FEASIBILITY.md) defines publisher attempts, valid acceptance, numeric commit, publication, receipt, reset start/completion and consumer restart separately. It identifies exactly which information reaches each consumer. The [trace model](IF11_TRACE_MODEL.py) compares those consumers and A/B/C numeric models with an independent full-history specification. The [receipt](IF11_RECEIPT.json) contains source identities and exact execution results.

## What newly has conditional support

**S: synchronous ordered response.** The consumer increments its own retained exact accepted-response count only on success, never on invalid rejection. With one outstanding acceptance, lossless publisher coordination, ordered delivery and drained old debt before a reset marker, it decodes exact rank. A separate reset acknowledgment is unnecessary. Restart works in the model only because the consumer preserves that context at action boundaries.

**X: explicit sequence/ordinal frame.** The consumer decodes binary sequence/rank fields generated by an explicitly hypothetical association owner. Ordered reset-completion frames establish the new context; old responses keep their original identity and may arrive after new ones. Equal old/new `(1,1)` payloads remain distinguishable. Bound retries return the original frame; retained consumer deduplication prevents a second logical result. Provider binding, retention, framing, restart persistence and storage are assumptions requiring review.

The completed deterministic run executes **14,327 cases with zero unexpected discrepancies, exit 0**. It includes 12,636 X lifecycle/restart traces, S drain controls, invalid attempts, queue saturation, tag reuse, retry identity and service-availability controls. An in-memory 256-bit-wrap mutation produces exactly one discrepancy and **exit 1**, demonstrating that the suite rejects that decoding defect. The mutant was never written to disk. These are finite source-language tests, not target qualification or proofs of unrestricted execution.

## What fails under named assumptions

An energy-only consumer that loses its accepted context sees the same restarted zero response when the required rank is 1 or 2. That interface cannot decode both. A finite closed consumer receiving only identical zero-energy events also cannot represent arbitrary exact rank without another information source. This does not refute all implicit representations.

An ACK alone cannot assign equal old/new results to their sequences. A finite generation tag aliases if reused while an old response remains live. Proven retirement can make reuse safe, but field width alone cannot. Neither result mandates a particular reset mechanism.

A Q-entry-only store cannot retain Q+1 accepted unpublished results when there is no other staging, compression, replay, storage or acceptance coordination. The positive controls honestly add storage or use a different coordinated schedule; neither control establishes that the current publisher can support it.

A stronger new family holds final numeric state and rank fixed while varying old unpaid results. For m blocks of `(1 or 2), then 32 zeros`, there are 2^m different owed result sequences but one final numeric state. The model checks m=1..5. The general conditional argument requires at least m retained information bits if all work is accepted during a stall, none is published, the complete boundary has no outside replay/store/timing information and later delivery must remain possible. Thus no fixed finite **closed boundary with those assumptions** can cover every such accepted prefix. The supplied AS does not establish all those operating assumptions, so this is not a finding that the entire AS is impossible.

## New dependencies that matter to a decision

S bounds live detector coordination under its proposed rendezvous, but its ordinary exact consumer count grows with accepted rank. X exposes that growth in the numeral owner, frames/parser and retained retry/dedup state. The Python witness uses arbitrary precision and diagnostic histories; it supplies no finite embedded allocation. A finite rank cap, mandatory reset or uncounted infinite memory would not close the gap under the active authority.

C still needs a real event-bound pre-tail provider in addition to any index service. With that service absent, A/B's local numeric models continue to compute correctly; C cannot supply the requested energies and retains the unpaid obligations. A coherent in-range snapshot from the wrong event can give 9 where 5 is required. Availability, truth of event binding and ownership are separate capabilities. No RN/C-HIST/RI service was approved or found.

All candidates need prospective acceptance/retention/flow evidence. Specifying a blocking call does not prove that an independent publisher avoids omissions. Reset does not erase old debt, and reporting an unavailable service is not delivery. Exclusively upstream RAM can be excluded only after ownership is established; shared/client/pinned memory, stack, staging, exact rank, debt and retries remain accounted by lifetime.

## Smallest follow-up decision

Obtain one actual consumer information/persistence inventory and one proposed acceptance/retention trace, then challenge it with the zero-prefix restart, equal-payload reset and Q+1 tests. Require named owners for every retained byte and unpaid result. This is the smallest package that can distinguish an assessable S/X contract from an information-starved interface or unsupported flow assumption. In parallel as inquiries, identify whether any candidate ordinal/context or snapshot supplier actually exists; an ordinary publisher is insufficient evidence.

The diagnostic authority can then determine whether a concrete contract preserves the AS, whether a new external service needs separate approval, or whether the intended finite operating model requires a material amendment. IF11 supplies conditional boundaries for that decision; it does not invent the available supplier or choose the resolution.
