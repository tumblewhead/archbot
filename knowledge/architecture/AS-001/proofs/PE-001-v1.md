# PE-001 v1: Independent review of PO-001

## Scope and assumptions

This proves the mathematical value bound and an abstract ring-buffer recurrence. It does not certify a firmware implementation. Let `N=32`, `M=4095`, and let every input `x_t` be an integer in `[0,M]`. Use zero for samples before time zero. The state immediately after accepting sample `x_t` consists of slots representing, in age order, `x_{t-31}, ..., x_t`, with negative-index samples interpreted as zero. The accumulator is the exact sum of the squares of those slots. On the next update, the oldest slot is read, the sum is reduced by its square, that slot is replaced with `x_{t+1}`, and its square is added.

For C mapping observations below, assume `uint32_t` exists and is an unsigned integer type of exactly 32 value bits, and `uint16_t` exists with exactly 16 value bits; the stored sample operands are values no larger than 4095. The exact C behavior remains conditional on the actual declarations and implementation.

## Theorem 1: universal accumulator range

For every `t >= 0` and every legal input sequence, the conceptual 32-element window sum `S_t` satisfies

`0 <= S_t <= 32 * 4095^2 = 536,608,800 < 2^29 < 2^32`.

**Proof.** Each of the 32 terms is the square of an integer in `[0,4095]`, including zero-valued prehistory. Therefore every term lies in `[0,4095^2]`; summing the termwise bounds gives the first inequality and upper bound. Direct arithmetic gives `4095^2 = (4096-1)^2 = 16,777,216 - 8,192 + 1 = 16,769,025`; multiplying by 32 gives `536,608,800`. Since `2^29=536,870,912`, this bound is strictly less than `2^29`, hence less than `2^32`. Thus every mathematical accumulator value is representable by 32 unsigned bits (and also by a signed 32-bit integer, though unsigned is the proposed type). This bound is tight: once 32 maximal samples are in the window, equality holds.

## Theorem 2: startup, update, and wraparound invariant

If the ring starts with all 32 slots zero, its write index points at the oldest slot, and each update reads/subtracts that slot before replacing it and advancing the index modulo 32, then after every accepted input the slots represent exactly the specified window and the accumulator equals its exact sum of squares. The subtraction is nonnegative, and the value after addition is at most `536,608,800`.

**Proof.** Base state before any samples: all slots are zero and accumulator is zero, so the invariant holds for the empty history. For the first 31 updates, the evicted slot is still a zero from prehistory or an earlier slot whose age has left the window; the operations remove precisely the outgoing window member and add the new member. More generally, assume before an update the ordered ring contents are the previous 32-window, with index `i` naming its oldest member, and `A` is their exact square sum. Because all terms are nonnegative, `A >= old^2`; therefore `A-old^2 >= 0`. Replacing that member by the incoming sample yields exactly the next window, so the exact new sum is `A-old^2+incoming^2`. This equals the stated recurrence and, by Theorem 1, is no greater than 536,608,800.

For the circular representation, advancing `i` to `(i+1) mod 32` after replacement restores the convention that the new index names the oldest slot. This argument is independent of the numeric index value, so it applies at index 31 (wrap to 0) and at every later wrap. The first 31 updates are covered without a separate special arithmetic rule because the initial zero slots explicitly encode absent history.

## Integer representation and C expression review

With a 32-bit unsigned accumulator, the represented accumulator and each post-subtraction/post-addition value fit. A 12-bit square is at most 16,769,025, which fits signed 32-bit `int`. If samples are stored as `uint16_t` on a target with 32-bit `int`, integer promotions convert each sample to `int` before multiplication; both products are thus signed `int` products and are representable. For an expression such as `sum -= old * old`, the product is computed before the compound assignment; usual arithmetic conversions for subtraction convert the nonnegative product to the unsigned accumulator type. This conversion is exact modulo 2^32 because the product is below 2^32. The invariant proves the unsigned subtraction's mathematical result is nonnegative, so no wrap occurs. For `sum += incoming * incoming`, the same promotion and conversion reasoning applies; the exact result is bounded by Theorem 1.

This conclusion is specific to the stated widths and operand range. If sample operands are wider, signed, or not range-checked, if multiplication is evaluated in a narrower type, or if a cast or alternate expression changes the operands, the argument must be redone. Integer promotions are determined by the implementation's `int` range and declared types; do not infer them solely from a Cortex-M label. Even on a conforming implementation where `uint16_t` promotes to `unsigned int` rather than `int`, the maximum unsigned product remains representable in a 32-bit unsigned type, but the actual types still require confirmation. The exact accumulator width must also be checked from `<stdint.h>` and compiler target definitions.

Subtract-before-add matters for a sequential update with a fixed-width accumulator. The invariant makes the subtraction safe, and the new window bound makes the subsequent addition safe. Adding first can exceed the final bound transiently: from a full window of 32 maximal samples, adding another maximal square before eviction would exceed 2^32, so a 32-bit accumulator can wrap. This is a counterexample to the alternative add-before-subtract order.

## Unresolved implementation obligations

- Inspect the actual C declarations, integer widths, compiler target, and relevant language version; confirm the range check happens before squaring.
- Verify the implementation reads the outgoing slot before overwrite, subtracts before adding, and advances the index exactly once modulo 32; establish that index initialization and slot initialization match this contract.
- Ensure no concurrent reader/writer or interrupt can observe or modify a partially updated state, or specify synchronization separately.
- Verify no alternate code path, reset path, or uninitialized memory breaks the invariant. No implementation was inspected for this review.
- Timing, atomicity, and memory layout are outside these mathematical theorems.

## Review disposition

The candidate mathematical bound and abstract recurrence in PO-001 are proved under the stated assumptions. This artifact is a proof package pending independent review; it does not establish implementation correctness, approve AP-002, or choose an architectural proposal. The existing architecture spine should link this artifact as a proof/review artifact, but must not claim `proven_by` until an independent reviewer accepts the proof and its implementation mapping is separately established.
