# PO-001: Rolling sum bound and invariant

## Candidate proposition

Assume each input sample is an integer in \(\{0,\ldots,4095\}\), the window length is 32, and missing prehistory is represented by zero. For every input sequence \((x_t)_{t\ge 0}\), define the conceptual window values \(w_{t,j}=x_{t-j}\) when \(t-j\ge0\), and \(w_{t,j}=0\) otherwise, for \(j=0,\ldots,31\). Define
\[
 S_t=\sum_{j=0}^{31} w_{t,j}^2.
\]
Then for every \(t\ge0\),
\[
 0\le S_t\le 32\cdot4095^2=536{,}608{,}800<2^{29}.
\]
Moreover, if a 32-slot ring buffer contains exactly these window values and an update evicts the oldest value \(o_t\) and inserts \(x_{t+1}\), the recurrence
\[
 S_{t+1}=S_t-o_t^2+x_{t+1}^2
\]
preserves the exact window sum; the intermediate subtraction is nonnegative and the post-addition value is at most \(536{,}608{,}800\). Thus a 32-bit unsigned accumulator is sufficient for the mathematical value and these ordered update intermediates.

## Assumptions and quantifiers

- Universal quantifier: all discrete times \(t\ge0\) and all legal sample sequences, with each sample in the declared ADC range.[^adc]
- The ring buffer is initialized to 32 zeros and the outgoing slot is the oldest sample in the represented window.
- Subtraction is performed before addition, and arithmetic is interpreted as exact integer arithmetic until machine-width sufficiency is concluded.
- The bound says nothing about a particular compiler's generated code, atomicity, or target WCET.

The range, 32-sample window, startup semantics, and overflow requirement come from the architecture statement.[^as]

## Prospective proof strategy

1. Establish the closed form for \(S_t\) from the window definition and use \(0\le w_{t,j}\le4095\) termwise to obtain the universal bound.
2. Verify the arithmetic: \(4095^2=16{,}769{,}025\), so the maximum is \(536{,}608{,}800\), below \(2^{29}\) and therefore below \(2^{32}\).
3. Induct on updates. The buffer invariant identifies the evicted value with the departing window member and the inserted value with the new member. Subtracting a squared member cannot make the sum negative; adding the incoming square yields the next closed-form sum, which obeys the same universal bound.
4. Check boundary cases explicitly: the initial all-zero state, early updates before the buffer fills, all-zero input, and all-4095 input.

This proof would support the exactness/overflow obligations for the arithmetic state in AP-002, but would not establish WCET or full firmware correctness.[^ap2]

## Possible counterexample or failure mode

The claim can fail if the buffer/index convention evicts a value outside the represented window, if initialization does not use zeros, if samples outside the declared range are accepted, or if the implementation performs a different arithmetic order or narrower intermediate operation. A code-level counterexample should be sought by checking startup and wraparound transitions; no such implementation has yet been inspected.

## Architectural value

If independently established and correctly mapped to the implementation, the result shows a 32-bit unsigned rolling accumulator can represent every required exact value without overflow. This gives AP-002 a concrete arithmetic-width justification and a reusable invariant for review. It does not select AP-002 over AP-001 because target cycle, flash, and full state costs remain unresolved under F-001.

## Independent validation needed

A proof engineer should formalize the state invariant, validate the induction through ring wraparound and startup, independently recalculate the bound, and inspect the eventual implementation's integer promotions and operation widths. The engineer should also test boundary transitions, while treating tests as corroboration rather than a substitute for the universal argument.
