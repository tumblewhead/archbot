## C-002 and F-001 comparison limits

The approved C-002 Option B limit remains 2,048 bytes of detector-attributable SRAM. Each candidate's proposal envelope allocates 904 bytes across charged categories plus 1,024 bytes of positive reserve, totaling 1,928 bytes and leaving 120 bytes unallocated beyond that reserve. This is a conditional AP allocation and enforcement plan, not measured consumption or physical proof. It accounts for state SRAM plus scratch, task and interrupt stacks, shared and other detector-attributable memory under its assumptions.

F-001's `state_sram_bytes` is a separate dimension from that total charged C-002 envelope. The assessments project 72 bytes of algorithm state for either candidate, conditional on representation and layout; this is not a measured total. AP-001's at-most-32 square/add work and AP-002's fixed recurrence operation count are operation/work descriptions, not measured cycles, target WCET, or proof of the 1 ms deadline. Flash bytes are unknown without a concrete build. Accordingly, no Pareto frontier or winner is supported. No target measurements, weights, or unsupported estimates are introduced here.
