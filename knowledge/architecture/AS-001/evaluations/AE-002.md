# AE-002: Stage-aware architecture evaluation

## Gate disposition

**UNRESOLVED — NO_DOWNSELECTION.** Neither proposal is stage-admissible because C-002 has no complete, bounded AP-stage whole-subsystem SRAM estimate. Therefore F-001 is not applied to either proposal. No proposal is selected. This is an AP-stage gate outcome, not a finding that either design exceeds 2048 bytes.

The five states used below are the VP-001 states. `DEFERRED` means final evidence is due later and the plan is credible; a future due date by itself does not justify it. `CONDITIONALLY_SATISFIED` records usable stage evidence with explicit remaining assumptions and tracked verification.

## C-002 conservative subsystem memory model

The hard limit is 2048 bytes of detector state SRAM. The current proposals permit only a partial lower-bound estimate, not a credible total. For either proposal, the sample history alone is 32 × 2-byte `uint16_t` = 64 bytes **if** this representation is chosen. AP-002 additionally requires a rolling sum; the accepted proof's mathematical bound is below 2^29, so a 32-bit unsigned representation would be 4 bytes. AP-001 also needs an accumulator while recomputing; a 32-bit accumulator is 4 bytes. Thus an illustrative data subtotal is at least 68 bytes for either, before any other state. This is not a declaration of concrete layout or an estimate of total subsystem memory.[^proof][^ap1][^ap2][^target]

The complete charged boundary must account for:

- persistent history, accumulator, index (at least one logical index; likely padded to native alignment), initialization/readiness counters, configuration/threshold state if charged, error/status state, and any temporary persistent data;
- struct and array alignment, padding between fields, and section/linker alignment;
- peak call-chain stack for update and any called helpers, including compiler spills and alignment;
- interrupt/preemption context and any detector-owned ISR stack/frame, plus concurrency/synchronization state;
- shared service/library state, buffers, scheduler or callback state, and other common memory charged to the detector;
- compiler/runtime overhead that occupies SRAM, static globals, heap/dynamic allocation if any, and unknown target-specific contributions.

For scale only, a 64-byte sample array plus a 4-byte accumulator has 1980 bytes of nominal budget remaining, but index, padding, the several unbounded categories above, and the accounting boundary are unspecified. No credible upper estimate or margin can be inferred from that remainder. The same accounting gap applies to both proposals. Consequently C-002 is `UNRESOLVED` for both; it cannot be marked `DEFERRED` under VP-001.

## F-001 application and minimum evidence to select

F-001 is unchanged: hard feasibility comes first; only feasible proposals are compared on Pareto dimensions (state SRAM bytes, worst-case cycles/update, flash bytes). Neither candidate clears all AP obligations because C-002 is unresolved (and AP-001 also lacks AP-stage R-002/R-003 evidence). Thus the outcome is **NO_DOWNSELECTION**, with no F ranking or invented score.[^merit]

Smallest evidence set to enable selection:

1. For both candidates, define the charged SRAM boundary and provide a conservative complete estimate with explicit alignment, stack, interrupt, shared-service, and unknown-overhead bounds and margin.
2. Provide AP-001's candidate-specific exactness and universal overflow argument; map PR-002's accepted abstract scope to AP-002's concrete contract/representation sufficiently to close AP-stage R-002/R-003 conditionally.
3. Provide comparable target worst-case cycles per update (or an adequately conservative target-specific analysis) and flash-byte evidence for both feasible candidates, with build/compiler conditions recorded.

If both pass feasibility and remain incomparable under unchanged F-001, obtain the documented stakeholder trade-off required by F-001.

## Scope and evidence limits

Inspected: AS-001, VP-001, F-001, both APs, all six VOs, PE-001-v2 and PR-002, AE-001 as historical context, and the machine-readable PR-002 disposition showing accepted scope `abstract_mathematics_only`. PR-002 supports AP-002 abstract arithmetic/correctness only; it explicitly leaves implementation, SRAM/flash, and WCET open. No raw dataset, firmware, compiler output, linker map, stack report, or target measurement was inspected. This evaluation is draft and does not approve a proposal or claim final validation.
